# Direct agent dialogue — 26 October 2026

Ordinary colleague handoffs now remain one-to-one exchanges. The host asks an accessible specialist for a contribution, the specialist replies, and the host uses completed contributions in its final answer. **Hold a meeting** remains the explicit way to gather participants at the shared table. The final release is deployed and healthy, and a real direct task completed successfully at **16:56:39 IST**, with both actual turns displayed in the live dialogue box and no meeting created.

## Using direct dialogue

Select an AI agent and send a task with **Hold a meeting** unchecked. The agent can answer directly or consult accessible colleagues as needed. During a direct exchange, the visitor walks to the colleague's desk, each real contribution appears under its speaker, and the visitor returns afterward. The dialogue box can be closed and reopened, and **Open full conversation** returns to the saved private thread. **View dialogue** on saved activity opens the recorded turn without replaying old movement.

To gather a group at the shared table, select **Hold a meeting** before sending. This keeps the existing meeting participants, transcript, and summary flow. Meeting movement takes precedence over a conflicting desk visit; unrelated visits can continue.

## Behavior and privacy

Previously, any task with a delegated contribution created a meeting. The coordinator now creates an `agent_meetings` record only when the saved `meeting_requested` flag is true. A direct exchange saves the host's request and specialist's reply in the existing private conversation. Desk visits and dialogue boxes are linked to those saved messages.

A task can ask at most two enabled, accessible colleagues, with no more than four model calls: host planning, up to two specialist turns, and final host synthesis. Later turns see earlier completed contributions. A failed specialist does not produce an invented reply or successful final summary; completed messages remain available. Simple questions can still receive one direct answer without a handoff. Existing task deadlines, pause checks, access checks, idempotent request IDs, and usage limits remain in place.

Conversation tables remain owner-private and subject to the requester's current department access. Another Super Admin does not gain access to someone else's thread merely by having the same role. Signed-in clients cannot insert agent answers or mark tasks complete. Business evidence and saved agent instructions continue to be read through the requester's authenticated database client.

`agent_events` has broader department visibility, so it contains only generic private-task activity and routing identifiers. The adapter first saves the private message and obtains its exact ID, then emits the generic routing event. It does not copy prompts, specialist answers, final responses, or arbitrary private metadata into the shared activity stream. Actual dialogue must be obtained through the existing authenticated conversation API and its row-level security checks. Public department activity retains its existing visibility rules.

Realtime notifications wake one serialized, ordered database reader, with a six-second catch-up poll and event-ID deduplication. The server captures the initial observation time before loading activity, so slow campus initialization does not lose later events. Existing activity does not automatically replay as live work. A dialogue read must match the exact authorized thread, saved message, sender, and recipient. Explicit authentication/access denial removes that thread's cached dialogue and cancels its visits. Account changes invalidate in-flight reads and callbacks so a prior session cannot repopulate private text.

The animation controller reserves both participants, queues conflicting visits, and ignores duplicate, stale, reversed, or mismatched phases. It uses bounded queue/wait/active timers and releases participants on interruption, disposal, or completion. Waiting does not invent a reply. A rejected animation is shown as interrupted rather than stuck in a walking state. Long speech bubbles are shortened for the campus while the dialogue panel retains the saved text. Ordinary activity cannot take over an agent reserved by a desk visit; explicit meeting speech remains available at the table.

The change uses existing conversation records and metadata; **no database migration is required**. It does not grant permission to publish, spend, sync providers, change accounts, approve work, or send external messages.
