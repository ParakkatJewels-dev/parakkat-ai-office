# Current working status — 26 October 2026

The office now has an independent status label for each currently active, onscreen agent. Work can remain visible after a short speech bubble ends. Labels distinguish real work, movement, conversation, meeting, and approval-waiting states; old activity or an old task description does not make an idle agent appear busy. Implementation, review, **299 tests**, the production build, the deployment isolation audit, and a real task's visible work lifecycle have passed.

## Behavior and source of truth

The earlier occupancy metric counted activity from the previous ten minutes, and temporary speech bubbles disappeared even when a task continued. The new occupancy/building counts and overhead labels use the same current-status source. Every onscreen active agent receives a label; dense views reposition labels rather than dropping agents after a fixed speech-bubble limit. Clicking a label opens that agent. Short current speech can appear alongside the retained work label.

Server work is recorded only while an actual instrumented callback is executing. Coverage includes named model calls, conversation hosts, design-library discovery/study, connector sync work, deterministic scheduled agents, and SEO source reads. Fixed labels describe the work, such as preparing a response, studying a past design, reading design folders, or syncing connected data. Waiting for another contribution remains distinguishable from speaking; the UI never invents a reply or model progress.

This deployment runs one Next.js Node process. Separately bundled API/job modules share a process-local registry through a `globalThis` symbol. Each independent work scope owns its own token, so one concurrent task ending cannot clear another task for the same agent. Nested work for the same agent reuses its outer scope; a specialist receives its own status. Entries clear in `finally` or on abort, renew every **20 seconds** under a **70-second lease**, and cannot outlive the caller's hard deadline, capped at **five minutes**. A process restart clears the registry. Old `think` events, completed usage records, and persisted `running` rows are not used to infer current activity.

The work-status API returns complete snapshots with at most **12 seconds** of client validity. The browser polls serially about every **four seconds**, converts server leases to local deadlines, and deducts request time. Clock skew, failed requests, empty snapshots, account changes, and unmounting cannot keep old work indefinitely visible. Local movement, direct visits, speech, meetings, and approval waits retain their distinct labels while their real presentation state exists.

The registry is intentionally limited to this single-process deployment. Before adding multiple app processes or replicas, replace it with shared live presence storage; otherwise each process would see only its own work. No database migration or database heartbeat writes are introduced.

## Privacy and preserved behavior

The API requires a signed-in user and filters agent IDs through the user's current role and department-head assignments, also excluding disabled agents. The globally readable agent roster alone does not grant access. Responses use `private, no-store` caching. Registry output contains fixed application labels and timestamps, with no task prompts, campaign names, replies, customer details, credentials, or private thread identifiers.

Actual dialogue remains governed by the existing private-thread access checks. Speech is cleared from the agent's state, legacy bubble HTML, status-card speech HTML, title, and accessibility label immediately when it ends or is canceled. This cleanup does not depend on a visible tab or the HUD animation loop. Hidden labels also discard their text. Account changes invalidate pending private reads and callbacks.

The instrumentation preserves callback results and errors, adds no provider requests, and does not grant new authority to publish, spend, sync unrelated systems, or approve work. Direct desk dialogue, explicit meetings, saved instructions, design-library progress, and existing business records remain intact.
